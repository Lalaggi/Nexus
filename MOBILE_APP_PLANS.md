# Mobile App Plans (Capacitor Android)

Tracks completed mobile-app work and future improvements for the Nexus Capacitor Android app.

---

## Done ✅

### Mixed content / networking
- `server.androidScheme: 'http'` so the local bundle loads at `http://localhost/` instead of `https://localhost/` — LAN server fetches over plain HTTP are no longer blocked as mixed content.
- `server.cleartext: true` retained for Android cleartext traffic policy.
- `android.allowMixedContent: true` as defense in depth (`WebSettings.MIXED_CONTENT_ALWAYS_ALLOW`).
- Stale `https://localhost` comment updated in `web/src/server.ts`.

### Boot flow
- Removed stale-closure early-return in `bootApp()` (`if (IS_NATIVE && !connected) return;`) that permanently blocked boot after reinstall.
- Mount `useEffect` now guards boot with `isConfigured()` so the Connect screen shows until a server URL is saved.
- Added a 15s default timeout to `api()` fetch calls in `web/src/api.ts` so boot fails over to an error screen instead of hanging indefinitely.

### Android system bars / orientation
- `android:screenOrientation="portrait"` in `AndroidManifest.xml` — locked to portrait on phone.
- `styles.xml` defines `AppTheme` / `AppTheme.NoActionBarLaunch` with `statusBarColor` / `navigationBarColor` set to `#141218` (Material 3 surface).
- `MainActivity` uses edge-to-edge mode + `WindowInsetsCompat` padding so content stays clear of status/nav bars.

### Mobile UI fixes
- Markdown tables: `white-space: nowrap` on `th`/`td` so wide tables scroll horizontally instead of stretching rows vertically.
- `.custom-model-id`: `min-width: 0` + `word-break: break-all` so long model IDs wrap cleanly instead of one-letter-per-line.
- `.dialog-actions` buttons: `white-space: nowrap` so "Change server" / "Save changes" stay on one line.

## Backlog 📋

> The canonical future-work pile is `FUTURE_PLANS.md`. Gestures and the settings
> redesign are tracked there too; this file keeps their mobile-specific detail.

### 1. Settings menu redesign (mobile-native)
**Goal:** Stop feeling like "desktop UI made to work on mobile." Current layout is a side-by-side category nav + content grid that doesn't translate well to narrow screens.

**Ideas:**
- Bottom-sheet or full-screen settings on mobile instead of a centered modal dialog.
- Category chips / segmented control at the top, content scrolling below (single column on narrow screens).
- Collapsible sections per category instead of hiding/showing whole panels.
- Group related fields (API keys, model ID, custom instructions) into cards.
- Make "Change server" / "Cancel" / "Save" more prominent and finger-friendly.
- Consider keeping side-by-side layout only on tablets / foldables (width breakpoints).

**Files involved:** `web/src/components/SettingsDialog.tsx`, `web/src/styles.css` (`.settings-layout`, `.settings-sidebar`, `.settings-content`).

### 2. Touch gestures
**Goal:** Reduce reliance on small buttons; match muscle memory from ChatGPT / DeepSeek.

**Ideas:**
- Swipe right from left edge → open chats sidebar.
- Swipe left → close chats sidebar.
- Swipe down on composer / message area → dismiss tasks & files sheets.
- Swipe left/right on a message → reveal quick actions (copy, edit, regenerate).
- Pull-to-refresh on chat list / settings?

**Files involved:** `web/src/App.tsx` (sidebar state), `web/src/components/Sidebar.tsx`, sheets (`TasksPanel`, `FilesPanel`), gesture library (e.g. `use-gesture` or custom touch handlers).

### 3. Mobile-specific layout polish
**Ideas:**
- Composer: make send button / model picker easier to hit with one thumb.
- Chat bubbles: increase touch targets for message actions.
- Landing page: larger touch targets for suggestions.
- Bottom navigation bar (if added) for core actions: New chat, Chats, Settings.
- Ensure `env(safe-area-inset-*)` isn't needed now that Java handles insets — verify CSS doesn't double-pad.

### 4. First-run / onboarding
**Ideas:**
- Clearer empty state when no server is configured.
- "Paste server address" hint pre-filled with common LAN format.
- Auto-detect local network Nexus servers (mDNS / broadcast)?

### 5. Performance / startup
**Ideas:**
- Splash screen tuning (currently 600ms).
- Lazy-load heavy components (Settings, panels) to speed boot.
- Cache last server + token so returning users skip Connect entirely.

## Notes

- The Capacitor config source of truth is `web/capacitor.config.ts`; `web/android/app/src/main/assets/capacitor.config.json` is regenerated by `npx cap copy` — always edit the TS file, not the JSON.
- Rebuild loop: `npm run build` → `npx cap copy` → `./gradlew :app:assembleDebug` → `adb install -r -d .../app-debug.apk`.
- Android SDK lives at `/tmp/opencode/android_sdk/`; `web/android/local.properties` points `sdk.dir` there.
